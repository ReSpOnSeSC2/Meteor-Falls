# RELEASE.md — building METEOR FALLS for Android

> S8 scope (Bible Prompt 41 adapted): the **debug APK** sideloaded onto a real
> phone. Play-Store packaging (signed AAB, listing, Proguard) stays Prompt 44.

## What wraps what

Capacitor 6 **wraps** the vite build — it never forks it (ADR-025). The
browser dev loop (`npm run dev`, the ADR-008 `window.pump/key/shot` QA driver)
is untouched; the phone runs the same `dist/` bundle inside a WebView with a
thin native shell (landscape lock, immersive mode, keep-awake, back-button=B,
audio focus, safe-area insets).

```
npm run android:apk     # build web -> validate -> sync -> gradle -> meteor-falls-debug.apk
```

That one script runs: `tsc --noEmit` → `npm run validate` (content gate) →
`vite build` → `cap sync android` → `gradlew assembleDebug` → copies the APK
to the repo root as `meteor-falls-debug.apk`.

## One-time machine setup (Windows, no admin needed)

The S8 build machine had no Java and no Android SDK; this exact sequence
produced the first APK. Everything lands under `%LOCALAPPDATA%` and can be
deleted to undo.

```powershell
# 1) JDK 17 (Temurin) -> %LOCALAPPDATA%\Java\jdk-17.x
curl.exe -L -o jdk17.zip "https://api.adoptium.net/v3/binary/latest/17/ga/windows/x64/jdk/hotspot/normal/eclipse?project=jdk"
Expand-Archive jdk17.zip -DestinationPath "$env:LOCALAPPDATA\Java"

# 2) Android cmdline-tools -> %LOCALAPPDATA%\Android\Sdk\cmdline-tools\latest
curl.exe -L -o ct.zip "https://dl.google.com/android/repository/commandlinetools-win-11076708_latest.zip"
Expand-Archive ct.zip -DestinationPath ct
New-Item -ItemType Directory -Force "$env:LOCALAPPDATA\Android\Sdk\cmdline-tools"
Move-Item ct\cmdline-tools "$env:LOCALAPPDATA\Android\Sdk\cmdline-tools\latest"

# 3) licenses + packages
$env:JAVA_HOME = (Get-ChildItem "$env:LOCALAPPDATA\Java" -Directory -Filter 'jdk-17*')[0].FullName
$SDK = "$env:LOCALAPPDATA\Android\Sdk"
& "$SDK\cmdline-tools\latest\bin\sdkmanager.bat" --sdk_root="$SDK" --licenses   # answer y
& "$SDK\cmdline-tools\latest\bin\sdkmanager.bat" --sdk_root="$SDK" "platform-tools" "platforms;android-34" "build-tools;34.0.0"

# 4) point the android project at the SDK (machine-local, git-ignored)
Set-Content android\local.properties "sdk.dir=$($SDK.Replace('\','\\'))"
```

Per-shell (or set permanently in the user environment):

```powershell
$env:JAVA_HOME = (Get-ChildItem "$env:LOCALAPPDATA\Java" -Directory -Filter 'jdk-17*')[0].FullName
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
```

## Building

```powershell
npm run android:apk
# -> meteor-falls-debug.apk at the repo root (~4 MB; the whole game is code)
```

Iterating on web code only: `npm run android:sync` then re-run gradle, or just
use the browser — the WebView runs the identical bundle.

Launcher icons and the splash are rendered FROM the sprite engine (ADR-002 —
no hand-drawn binaries) and **git-ignored**: `npm run android:sync` runs
`art:appart` automatically, so a fresh clone produces them on first build.
Opening `android/` directly in Android Studio before ever running the npm
chain will report missing mipmap resources — run this once first:

```powershell
npm run art:appart
```

## Installing on the phone

1. Phone: Settings → System → Developer options → **USB debugging** on
   (tap Build number 7× if Developer options is hidden).
2. `adb` lives at `%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe`:

```powershell
adb install -r meteor-falls-debug.apk
```

Or copy the APK over (Drive/USB/messenger-to-self) and open it — allow
"install unknown apps" for whatever app opens it.

> An app **update** (install -r with a higher or equal versionCode, same
> signature) keeps localStorage — the ADR-018 save slots survive. Uninstalling
> wipes them; that is Android policy, not a bug. The §B1 IndexedDB driver
> remains the durability follow-up and lands behind `SaveStorage` (ADR-018).

## Signing

- **Debug builds** are signed automatically with the Android debug keystore
  (`%USERPROFILE%\.android\debug.keystore`, generated by the tooling on first
  build). Nothing to manage, nothing to commit.
- **Release keystore** (Prompt 44 will use it — generating it early is fine):

```powershell
& "$env:JAVA_HOME\bin\keytool.exe" -genkeypair -v `
  -keystore meteor-falls-release.keystore -alias meteorfalls `
  -keyalg RSA -keysize 2048 -validity 10000
```

  Keep the keystore and its passwords **outside the repo** (a password
  manager + offline backup). `.gitignore` refuses `*.keystore`/`*.jks` as a
  backstop. Losing it means losing the Play identity; committing it means
  anyone can ship as you. Neither is recoverable.

## What the native shell does (and where)

| Concern | Where |
|---|---|
| Landscape lock | `android/app/src/main/AndroidManifest.xml` (`sensorLandscape`) |
| Immersive fullscreen + re-hide after dialogs | `MainActivity.applyImmersiveMode()` |
| Keep-awake during play | `MainActivity` (`FLAG_KEEP_SCREEN_ON`) |
| Cutout edge-to-edge (feeds `env(safe-area-inset-*)`) | `MainActivity` (`LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES`) |
| Touch overlay inside the insets | `src/engine/native.ts` → `UIScene.layoutControls()` |
| Back button = B (cancel) | `src/engine/native.ts` (`App.backButton` → `INPUT.tapBtn('B')`) |
| Audio focus on calls/app switch | `src/engine/native.ts` (`appStateChange` → `AUDIO.focusLost/Gained`) |
| Durable storage flag | `src/engine/native.ts` (`navigator.storage.persist()`) |
| Icons + splash from the sprite engine | `tools/render-appart.ts` (`npm run art:appart`) |

## Device QA gate

Input is the release gate (ADR-024/ADR-025). The on-device checklist and its
log live in **docs/QA.md** — a debug APK is "done" only when that table is
green on a real phone, touch-only AND Bluetooth-pad-only.
